# MRS app audit (13 Nov 2026) and v6.3.1 messaging fixes

Scope: `MRS_Dashboard/app`, 59 files, about 17,600 lines of Python plus the workflows.

Method:
- static analysis (ruff: pyflakes, bugbear, pylint errors);
- the repo's own test scripts;
- a full AppTest run of `app.py`;
- a manual review of the production paths: the daily MRS update, the scanner, the dashboard cards and the workflows.

`.streamlit/secrets.toml` and the token file were not read.

## A. Messaging fixes applied (v6.3.1)

1. **One owner per question.**
   - The Market context card no longer sizes positions: the pedal does.
   - The card shows the cell for today's exact state (MRS side × SPY phase), not the regime and the phase separately.
   - Today: "Risk-off side + OUT: +0.10 to +0.17R (random +0.17)", with the strongest cell (risk-off + dip zone, +0.38 to +0.42R) for scale.
   - Cells with fewer than 1,000 Deep dips are flagged as anecdotal.
   - `context_card.py` e63d40a5.
2. **One SPY-vs-50-day number.**
   - The card now uses the pedal's own value. The risk snapshot is built before the card, and the pedal panel only renders it.
   - The pedal state REBOUND WINDOW is renamed DIP ZONE, and the gauge reads "dip zone". The phase track reads "DIP ZONE · rebound window".
3. **Follow-through day label:** the date only, no "today" / "N sessions ago" (the scan can be a session behind the MRS).
4. **Allocation footer:** "the tickets use ATR(10), as tested; stock setups use ATR(14)".
5. **Pedal wording:** "A-setups" → "your planned setups".
6. **Bug found during testing:** the card printed the MRS percentile flag ("LOWER QUINTILE") as the regime tag. It now uses the band, or DEEP RISK-OFF / DEEP RISK-ON only.
